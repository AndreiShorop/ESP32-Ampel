Architektur · Datenfluss · Betrieb

Wie das System zusammenspielt

Sensoren liefern Zustände an den ESP32. Die Firmware steuert daraus die Ampel und stellt Messwerte im lokalen WLAN bereit. PC-Logger und Backup laufen unabhängig davon.

ESP32 · Arduino · LittleFSWebserver, SQLite-Logger und PowerShell-Backup

02 / Datenfluss

Was beim Start und im Betrieb passiert

  1. Firmware startetInitialisiert Sensoren und Ampelausgänge, danach LittleFS und WLAN-Verbindung.
  2. ESP32 tritt dem 2,4-GHz-WLAN beiSSID und Passwort kommen aus include/config.h. Nach Verbindung startet der HTTP-Server auf Port 80.
  3. Sensorwerte werden aktualisiertDHT22 wird etwa alle 2,5 Sekunden gelesen. Der PIR-Zustand wird in jeder Schleifenrunde geprüft.
  4. Webseite erhält StatusDer Browser lädt HTML aus LittleFS und fragt /api/status alle 1,5 Sekunden ab.
  5. PC protokolliert separatPython fragt denselben JSON-Endpunkt alle 30 Sekunden ab und fügt eine Zeile in SQLite ein.
  6. Backup erstellt lokale KopiePowerShell kopiert die Datenbankdatei sofort und danach jede Minute. Backup ersetzt jeweils die vorherige Kopie.

05 / Persistenz

Messwerte und Sicherung

SQLite auf dem PC

Logger schreibt in db\sensordaten.db, typischerweise alle 30 Sekunden. Ungültige Temperatur- und Feuchtewerte werden als SQL-NULL abgelegt. Die Datenbank entsteht beim Loggerstart.

Rotierendes Backup

BackupService\backup.ps1 erstellt C:\vscode\ESP32-Ampel\BackupService\Backup\sensordaten_backup.db. Jede Sicherung ersetzt die vorherige; es entsteht kein Archiv pro Tag.

Messdaten
C:\vscode\ESP32-Ampel\db\sensordaten.db
Backup-Kopie
C:\vscode\ESP32-Ampel\BackupService\Backup\sensordaten_backup.db
Erfolgslog
BackupService\Logs\Success\success.log
Fehlerlog
BackupService\Logs\Error\error.log
!Backup läuft nur, wenn backup.ps1 aktiv ist. Logger und Backup sind zwei getrennte Prozesse. Stoppen mit Ctrl+C im jeweiligen Terminal.

07 / Start & Diagnose

Betrieb und häufige Fehler

Messwert-Logger starten

Im Projektordner PowerShell öffnen. IP durch die Adresse aus dem Monitor ersetzen.

python tools\log_sensor_data.py --url http://<ESP32-IP>/api/status --database "db\sensordaten.db"

Mit Ctrl+C stoppen. PC muss im selben WLAN wie ESP32 sein.

Backup starten

Logger zuerst starten und mindestens eine Messung speichern. In zweitem PowerShell-Terminal:

cd C:\vscode\ESP32-Ampel
.\BackupService\backup.ps1

Mit Ctrl+C stoppen. Falls Richtlinie blockiert: Set-ExecutionPolicy -Scope Process Bypass.

Webseite lädt nicht

Monitor-Ausgabe prüfen. ESP32 und Browser müssen im gleichen WLAN sein. URL mit http:// öffnen. Falls LittleFS-Dateien fehlen, pio run --target uploadfs ausführen.

WLAN-Verbindung schlägt fehl

SSID und Hotspot-Passwort in der lokalen Konfiguration vergleichen. ESP32 braucht 2,4-GHz-WLAN; beim iPhone-Hotspot „Maximale Kompatibilität“ aktivieren.

DHT22 zeigt --.-

Versorgung, DATA an GPIO 4 und Pull-up-Widerstand prüfen. Code erwartet DHT22/AM2302.

Backup schlägt fehl

Logger muss DB zuerst anlegen. Dann Fehlerlog unter BackupService\Logs\Error\error.log ansehen und prüfen, ob Quelldatei existiert.
